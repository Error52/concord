# Concord: передача на доработку

**Последнее дополнение — LAN, 13 октября:** читать `docs/LAN.md` и `docs/VERIFICATION-LAN.md`. Общая версия использует HTTPS, Secure cookies, настоящий backend и Wi-Fi IP LiveKit. Собственное verification-письмо доступно через `/auth/email/demo` только при DEMO_MAILBOX=true и после входа; reset/чужие письма не возвращаются. Это demo, не доказательство владения email. При реальном SMTP оставить DEMO_MAILBOX=false. Media cookies связаны с действующей session family в PostgreSQL; не заменять эту проверку коротким Redis revocation cache. Windows firewall/CA запросы были отменены: физический клиент ещё не проверен. Прежние проверки ниже относятся к указанным снимкам.

Последнее обновление: **13 октября 2026**. Дополнительно прочитать `docs/REGISTRATION.md`: полноценное подтверждение почты, outbox, исправления сессий и разделение frontend сборки. AppShell/LiveKit загружаются после входа; не возвращать весь SDK в начальный guest bundle без измерения.

Это работающий локально мессенджер с React/TypeScript, собственным Node backend, PostgreSQL, Redis и LiveKit SFU. Пользователь просит надёжную работу функций, качественный голос и быструю, плавную демонстрацию **игр и видео**, с разумной нагрузкой на слабый компьютер.

## Обязательные ограничения пользователя

- Сохранять существующий дизайн: цвета, шрифты, иконки, структуру экранов, визуальный язык. Адаптивы и исправления поведения допустимы; редизайн не нужен.
- Приоритет: звук, задержка и плавность демонстрации. Не подменять реальную передачу звука/видео имитацией в приложении. Синтетические источники допустимы только в тестах.
- Сохранять данные. Разрушительные API-тесты запускаются исключительно на отдельной базе с test в имени и отдельной ненулевой Redis DB.
- Изменения проверять сборкой, типами и соответствующими тестами; записывать реальные результаты и границы проверки.

## С чего начать

1. Прочитать `QUICKSTART.md`, `docs/HANDOFF.md` и `docs/VERIFICATION.md`.
2. Установить зафиксированные зависимости через pnpm 11.25.0 с `--frozen-lockfile`. Не обновлять SDK или сервер LiveKit без проверки их совместимости.
3. Запустить собственный стек. Архив содержит исходники и тестовые отчёты; пользовательские базы, секреты, зависимости и бинарные программы в него не включены.
4. Проверить исходное состояние перед изменениями. Не считать цифры из отчёта гарантией для другой машины или сети.

## Ключевые места

- `frontend/src/webrtc/voiceEngine.ts`: владение комнатой и медиа, отмена асинхронного захвата, публикация, VAD/PTT, восстановление соединения.
- `frontend/src/webrtc/mediaPolicy.ts`: голос Opus до 96 кбит/с mono, звук демонстрации до 192 кбит/с stereo; необязательная подсказка буферу браузера.
- `frontend/src/webrtc/streamQuality.ts`: профили, пределы по CPU, гистерезис нагрузки, H.264/VP8.
- `frontend/src/webrtc/stats.ts`: настоящие WebRTC counters, RTT, потери, битрейты, фактический буфер воспроизведения.
- `frontend/src/components/voice/VideoTile.tsx`: повторно подключать видео только при смене конкретной дорожки. Не удалять React-owned video из обработчиков LiveKit.
- `frontend/src/styles/responsive.css`: исправления размеров и прокрутки без смены дизайна.
- `backend/src/websocket/gateway.ts`: порядок авторизации/первого heartbeat.
- `backend/test/environment.ts`: защита тестовых баз; не ослаблять.

## Важные технические решения

Сейчас демонстрация публикуется одним слоем, без simulcast: маленький мини-плеер не должен принудительно превращать источник в низкое разрешение. Для всех экранных профилей используется `maintain-resolution`: при `maintain-framerate` Chrome на этом стенде снижал 1080p до 640×360 даже на localhost. Нагрузку CPU отдельно уменьшает контроллер capture constraints; сети помогает нативный congestion control. Возврат simulcast или другой degradation policy требует проверок реального разрешения у зрителя, включая мини-плеер.

Не объединять голос и музыкальный звук демонстрации в одну обработанную mono-дорожку. Для screen audio отключены voice DTX/RED и обработка шума/эха; приёмник сохраняет stereo. При полной потере комнаты экран останавливается, пользователь запускает его заново; автоматически открыть системный picker без жеста пользователя нельзя.

Сначала проверить реальные слабые устройства, игру под GPU/CPU нагрузкой, Safari/iPhone, потери/джиттер/ограниченный канал, TURN через внешнюю сеть и Docker. Здесь такие проверки не выполнены; локальные измерения и список уже выполненных сценариев приведены в отчёте. Доработку выбирать по воспроизводимой проблеме, не по предположению.
