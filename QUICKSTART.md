## Локальный стек через Docker

Нужны Node.js 24 и Docker с Compose v2. Открыть терминал в корне распакованной папки `concord`:

```sh
node scripts/dev.mjs up
```

Команда создаёт `.env` со свежими случайными секретами, затем собирает и запускает стек. Существующий `.env` сохраняется. Новый стек открывается на **http://localhost:8080**, локальные медиа-порты — TCP 7981 / UDP 7982. Первый запуск требует сети для загрузки образов и зависимостей.

Демо: `alice@concord.local`, `bob@concord.local`, `carol@concord.local`, `dave@concord.local`; пароль **demo12345**. Alice — администратор. Для проверки двух участников откройте второй браузер или окно инкогнито с Bob.

```sh
node scripts/dev.mjs logs
node scripts/dev.mjs stop
```

Остановка сохраняет Docker volumes. Инициализация нового `.env` проверена; Docker здесь не установлен, поэтому сборка контейнеров и сетевой маршрут Docker ещё требуют проверки на принимающей машине. Проверенный стенд работал без Docker на Windows с теми же исходниками и LiveKit 1.13.9.

`POSTGRES_INITDB_ARGS` устанавливает Unicode-локаль только при создании нового volume. Для существующей базы с неправильной локалью требуется отдельная миграция с резервной копией; не удалять volume ради поиска.

## Разработка и тесты

Использовать Node 24.19.0 / pnpm 11.25.0 (проверенные версии). Установить pnpm указанной версии, затем в каждой папке выполнить:

```sh
cd backend
pnpm install --frozen-lockfile --ignore-scripts
pnpm typecheck
pnpm build
cd ../frontend
pnpm install --frozen-lockfile --ignore-scripts
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm test:webrtc
```

API-тесты с изолированными PostgreSQL и Redis из корня проекта:

```sh
node scripts/dev.mjs test-api
```

Тестовый compose имеет собственное имя проекта `concord-tests`, не публикует порты и не использует volumes основного приложения. API-тесты очищают свою базу/Redis; встроенная защита требует `NODE_ENV=test`, имени PostgreSQL с сегментом `test` и Redis DB ≥1. Имя в пароле или hostname не считается тестовой базой.

Браузерные тесты запускать против **отдельного seeded стека**: они регистрируют пользователей, отправляют сообщения и меняют mute у демо-аккаунтов. Команды и переменные — в `docs/HANDOFF.md`. Для localhost доступен микрофон/камера; с другого устройства нужен HTTPS и правильно объявленный LAN/public IP медиа. Настройки развёртывания для LAN/VPS находятся в исходном README и `scripts/setup.sh`; в этом обновлении внешнее развёртывание не проверялось.

Для ручной проверки в браузере: разрешить микрофон и камеру, выбрать экран/окно/вкладку, включить «Поделиться звуком». Наличие системного звука зависит от ОС, браузера и выбранной поверхности. У «Авто» предел до 1440p/60; при небольшой мощности — 1080p/30, далее нагрузка снижается по статистике. Режим не повышает разрешение реального источника.
