## Осталось в Windows

Установка CA и узкие правила firewall не завершены: системные запросы были отменены. Поэтому нельзя считать доступ физически другого устройства подтверждённым. На сервере открыть **Enable-Concord-LAN.cmd**, разрешить UAC. На каждом Windows-клиенте открыть **Install-Concord-Certificate.cmd**, подтвердить CA Concord LAN, перезапустить браузер. Другим устройствам передать **concord-lan-client.zip** и адрес сайта. Это LAN, без публичного хостинга. Подробности: LAN.md.

## Изменения

- HTTPS через Caddy 2.11.7; официальный Windows-архив проверен по SHA-512 из опубликованного checksum-файла. CA и данные сохраняются, private keys остаются только на сервере.
- LiveKit объявляет Wi-Fi IPv4, вместо 127.0.0.1. Signalling и gateway работают через WSS; медиа — отдельный UDP/TCP.
- Прокси сохраняет настоящий IP от доверенного loopback Caddy, снимает поддельные Forwarded-заголовки у прямых клиентов. Пользователи не делят один общий rate limit из-за адреса прокси.
- Регистрация/вход работают через общий backend. При выбранной локальной демопочте пользователь после password login открывает только собственную действующую verification-ссылку; других писем/reset links endpoint не отдаёт. По умолчанию DEMO_MAILBOX=false; включение demo не доказывает владение настоящим email. Внешних писем по-прежнему нет.
- Исправлен долгий доступ со скопированной media cookie после logout/reset: durable проверка действующей session family в PostgreSQL, с сохранением нормальной rotation.
- Docker LAN-конфигурация получает HTTPS/Secure cookies, IP LiveKit/TURN и demo mode без замены существующих секретов/volumes. Docker здесь отсутствует и не запускался.
