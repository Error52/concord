# Concord — дополнительный аудит входа, состояния и звонков

Проверка начата 16 и завершена 17 октября 2026. Дизайн и CSS сохранены: production CSS остаётся `main-5WAF5OHU.css`. Предыдущие исправления установки, Docker/npm, почты и конкурентной отправки описаны в [прошлом отчёте](VERIFICATION-CONCURRENCY-2026-10-16.md).

## Найденные сбои и исправления

| Область | Исправление |
| --- | --- |
| Вход и 2FA | Выдача сессии повторно проверяет пароль и состояние 2FA под общей блокировкой с изменением учётных данных. Парольный вход не обходит только что включённую 2FA. Устаревший MFA ticket после отключения/замены секрета отвергается. |
| Настройка 2FA | Устаревший setup не перезаписывает действующий секрет, не переживает смену пароля и не удаляет новый секрет при старой операции disable. При обязательном подтверждении email настройка 2FA до подтверждения запрещена: чужой неподтверждённый адрес нельзя запереть своим TOTP. |
| Сессии | Повтор refresh-токена и параллельная ротация не оставляют действующего потомка отозванной семьи. Смена пароля из уже отозванной семьи запрещена. Потеря Redis-ключа не возвращает доступ: активность семьи проверяется индексным запросом PostgreSQL. Ротация сама по себе не прерывает ещё действующий access token той же семьи. |
| Сброс пароля и JWT | Исправлен deadlock между запросом нового письма и подтверждением сброса. JSON-null JWT header и неверные UUID/ownership claims отклоняются без HTTP 500 и неверного SQL cast. |
| Роли | Назначение уже существующей нижней роли также проверяет выдаваемые права: MANAGE_ROLES не позволяет добавить себе ADMINISTRATOR. Неизвестные и переполненные permission bits дают 400. Изменение роли, её создание/удаление и назначения сериализуются, права читаются внутри транзакции. |
| Иерархия модерации | Смена чужого nickname и голосовая модерация защищают владельца и более высокие/равные роли. Собственная смена nickname и разрешённое управление своим voice состоянием сохранены. |
| Конкурентные роли и вход | Используется `FOR NO KEY UPDATE`: роль не создаётся по устаревшему разрешению, а FK-проверка входящего участника не образует цикл с membership lock. |
| Администраторы платформы | Два параллельных снятия прав не оставляют платформу без последнего администратора; авторизация и audit выполняются в той же транзакции. |
| Друзья и блокировки | Встречные запросы образуют одну дружбу. Block и request не оставляют запрещённый pending request. Список отношений снимается одним SQL snapshot; публикации одного пользователя упорядочены. Поздний HTTP-ответ не заменяет новые WS/ready данные. Hydration использует уже выделенный DB client и не истощает пул. |
| Вложения | Parent-first lock и условное удаление защищают от параллельного удаления сообщения/файлов. Удаление двух последних файлов не публикует два `message:delete`; upload, привязанный во время удаления, не оставляет пустое сообщение. Поздняя hydration проверяет существование сообщения. |
| Приватные файлы | Ответы используют `private, no-store`, чтобы браузер не переиспользовал ранее авторизованный файл после выхода/смены аккаунта. Media cookie проверяет UUID пользователя до SQL. |
| Прочитанное и упоминания | Сервер выдаёт ревизию каждому изменению read state. Повторные, поздние и переставленные события не откатывают счётчик. Намеренная отметка «не прочитано» может двигать marker назад при новой ревизии. Старое упоминание, закоммиченное после более нового marker, остаётся прочитанным. Собственные системные сообщения и история звонка также продвигают ревизию. |
| Снимки сервера | HTTP refresh воспроизводит события, пришедшие во время загрузки. Он не возвращает удалённые каналы/участников, старые профили и voice состояния, не откатывает последний message ID. Новый ready очищает недоступные роли, permissions и старую активность. |
| Черновики и повтор отправки | Account/channel/thread draft переживает StrictMode и повторное открытие. Поздняя ошибка восстанавливает текст в уже открытом заново редакторе. Ограниченный cache сохраняет исходный nonce для повтора того же запроса после навигации. GIF не стирает набранный текст. |
| GIF и профили | Ответы старого GIF-поиска/пагинации и старые profile response/error игнорируются при смене запроса или карточки. |
| Gateway | Зависший CONNECTING и отсутствие ready завершаются таймаутом с переподключением. Shutdown ждёт завершения очереди auth/messages и асинхронной очистки presence до закрытия DB. |
| Голосовое присутствие | Состояние привязано к реальным participant/room SID. Старые joined/left/room_finished и leave из старой вкладки не стирают новое соединение. Reconciliation сохраняет SID при пропущенном webhook. SFU 404 означает закрытую комнату; 503 не считается доказательством выхода. |
| Привязка медиа к входу | Новые grants содержат подписанный сервером session ID. Logout/reset/revoke снимают участника этой семьи, сохраняя другое устройство. Webhook/reconciliation проверяют действующую семью, включая допустимую ротацию, и отвергают чужую/отозванную/неверную привязку. Legacy без session ID удаляется после пятиминутного переходного окна процесса. |
| История звонков | Одна запись создаётся по последнему реальному SFU departure и серверной длительности. Дубли end/leave не размножают историю. Ответ через DM sidebar не считается пропущенным. Непринятый вызов сохраняется даже после истечения 45-секундного ring: marker хранится в PostgreSQL. Одиночный вход без звонка не создаёт пропущенный вызов. |

## Проверки

- Backend **128/128**, frontend **86/86**. Это 47 новых backend-регрессий и 14 новых frontend unit-проверок сверх предыдущего прогона. TypeScript и production build обеих частей проходят.
- Chrome: общий E2E **17/17**, edge cases **10/10**, recovery **11/11**, composer **6/6**, GIF/profile **5/5**; браузерных ошибок нет. Для GIF тесты используют изолированные ответы провайдера и не требуют внешнего API-ключа.
- Регистрация, подтверждение/повтор письма с настоящим 60-секундным cooldown, отказ старой ссылки, reset из вошедшего аккаунта, вход с новым паролем и восстановление загрузки JS проходят. Начальная загрузка гостевого JS — около **305 КБ** без сжатия.
- Адаптивы: **120 проверок / 16 размеров**, без ошибок и изменения CSS. WebRTC loopback передаёт тестовое Opus-аудио.
- Изолированная старая auth-реализация проваливает все 13 новых auth-регрессий. Четыре гонки вложений и потеря expired-ring истории также отдельно воспроизведены до исправления. Такие baseline-копии не входят в исходники приложения.
- Полный прогон использует отдельные PostgreSQL и Redis DB; пользовательские данные не очищаются. После перерыва QA PostgreSQL запущен на другом тестовом порту из-за занятого прежнего порта; настройки установки приложения не менялись.
- Docker Compose недоступен на этом Windows-хосте: локально соответствующая проверка помечена skipped. Linux Compose и обе Docker-сборки проверяются workflow GitHub Actions для опубликованного коммита.

## Медиа

Два Chrome-контекста, локальный LiveKit, синтетический canvas 1920×1080 при 60 fps и стереотест с тонами 220/880 Гц. Тестовая сборка даёт доступ к engine только для fault injection; после проверки восстановлена штатная production-сборка.

| Сценарий | Полученное видео | Частота | Первый кадр | Задержка median / p95 |
| --- | --- | --- | --- | --- |
| H.264, включая полный reconnect | 1920×1080 | 52,78 fps | 830 мс | 50,5 / 53,6 мс, 176 измерений |
| Получатель только VP8 | 1920×1080 | 51,66 fps | 231 мс | 51,2 / 55,7 мс, 172 измерения |

Стереоканалы разделены. Пройдены full reconnect с новыми декодированными HD-кадрами, signaling recovery, server mute/unmute с возобновлением audio bytes, сохранение self-mute, смена источника и возврат доступа к микрофону. Отмена незавершённых mic/camera/screen capture, быстрые повторные включения и освобождение треков/AudioContext после disconnect также проходят. Ошибок браузера нет. Время первого кадра — результат отдельного прогона и не сравнение двух кодеков в одинаковых стартовых условиях.

Обезличенные логи и JSON находятся в [results](results): файлы `*-deep.*`. Сетевые адреса из media-отчётов удаляются перед публикацией.

## Ограничения и обновление

Revoke и допуск участника не являются общей транзакцией с SFU. При гонке участник может кратко попасть в комнату до webhook или следующей reconciliation (цикл 30 секунд). При отказе SFU удаление остаётся best effort. Переходное окно legacy составляет пять минут после старта backend; перезапуск начинает его заново. Новые API grants всегда привязаны к сессии. Старые backend-реплики нужно завершить.

Проверки на одном компьютере не измеряют настоящий слабый ПК, второе устройство в LAN, WAN, реальную игру и голосовую задержку mouth-to-ear. Успешные тесты не доказывают отсутствия всех возможных ошибок.

Нужны миграции **008–010**; штатный backend применяет их автоматически. Обновляйте обе части совместно, сохраняйте `.env`, uploads и volumes. Незавершённые старые MFA/setup начинают заново; включённые 2FA-секреты сохранены. Команды и детали — в [UPGRADING.md](UPGRADING.md).
