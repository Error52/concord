## Что исправлено

- Чат получил ограниченную область прокрутки; composer остаётся внутри окна. Адаптивы, формы, меню, ветки, диалоги, сенсорная прокрутка и мини-плеер проверены на узких/низких экранах.
- Сохранены цвета, шрифты, иконки и стиль. В медиа-обновлении CSS не изменялся относительно предыдущей исправленной версии. Добавлены строки реального буфера в существующее окно статистики и обновлены подписи качества.
- Backend больше не теряет немедленный heartbeat во время асинхронной авторизации gateway. Фоновая задача не падает необработанным rejection при недоступном Redis.
- Исправлен русский поиск в локальной Windows-базе переносом в правильную Unicode-локаль после резервного копирования. Для новых контейнерных БД задан UTF8/C.UTF-8.
- LiveKit 1.9 на исходном стенде не доставлял медиа с клиентом 2.22.3; сервер заменён на 1.13.9 и зафиксирован в compose.
- Голос теперь имеет бюджет Opus до 96 кбит/с mono, DTX и RED; звук демки — отдельный raw stereo до 192 кбит/с. Это потолки кодирования, не постоянный фактический битрейт и не гарантия субъективного качества.
- «Авто» рассчитан на игры/видео: до 1440p/60, до 12 Мбит/с. <12 логических CPU: максимум 1080p; ≤4: 30fps. Контроллер после 3 плохих сэмплов снижает нагрузку, после 20 здоровых восстанавливает. Нативное ограничение сети не выдаётся за перегрузку CPU.
- Одна дорожка screen video, H.264 при поддержке, VP8 fallback. Для экранных профилей сохраняется разрешение кодировщика; иначе на тестовом Chrome даже ручной 1080p60 уходил в 640×360.
- Опциональный `jitterBufferTarget` имеет нижние ориентиры 20 мс для голоса / 40 мс для screen и растёт с джиттером до 160 мс. Браузер сохраняет управление фактическим буфером, синхронизацией и потерями; unsupported/rejected setter не ломает звонок. Реальные величины измеряются из delta `jitterBufferDelay / jitterBufferEmittedCount`.
- Снятие серверного мута восстанавливает публикацию и передачу байтов. Отдельно сохранено состояние ручного mute при deaf/undeaf. После отказа микрофона доступно повторное включение.
- Захват микрофона/камеры/экрана имеет проверку владения комнатой и номера операции. Поздний результат разрешения после disconnect останавливается до публикации. Освобождение комнаты забирает ресурсы синхронно до await, поэтому не разрушает новый звонок.
- Source switching, остановка экрана и отключение останавливают audio/video и дополнительный audio input. Неизменившаяся видеодорожка не detach/attach при чужом media событии; обработчики SDK не удаляют React video DOM.
- Notification AudioContext при простое приостанавливается, oscillator/gain освобождаются; после звонка нет постоянно работающего уведомительного DSP.

## Команды браузерных проверок

Установить зависимости и Chromium согласно QUICKSTART. `BASE_URL` — адрес отдельного seeded UI. `EXPECT_VOICE=1` делает voice join обязательным. Если нужен установленный Chrome, задать `CHROMIUM_PATH`, иначе Playwright использует свою Chromium.

В PowerShell, из `frontend`:

```powershell
$env:BASE_URL='http://localhost:8080'
$env:EXPECT_VOICE='1'
$env:AUDIT_DIR='test/results/layout'
$env:SCREEN_DIR='test/results/screen'
$env:MEDIA_DIR='test/results/media'
npm run test:e2e
npm run test:responsive
npm run test:screen
npm run test:media
```

Тесты медиа запускать последовательно, без параллельных тяжёлых процессов: два браузера, synthetic 1920×1080 canvas с временным кодом и отдельные тоны 220/880Hz для stereo. Рабочий стол/пользовательские файлы не захватываются. Замер картинки основан на закодированном времени и `requestVideoFrameCallback`; это не RTT, не задержка физического монитора и не measurement голоса mouth-to-ear.

`QUALITY=auto|1080p60|1080p30|720p30|text` выбирает профиль, `BENCH_ONLY=1` пропускает дальнейшие lifecycle-сценарии. `MOTION=0` оставляет неподвижную картинку. `MEDIA_DIR` задаёт папку JSON/PNG. Полный `test:media` проверяет stereo separation, прерывание сигналинга, серверный mute/unmute, source switch, отказ и повтор mic, отмену pending mic/camera/screen, отсутствие живого capture и работающего DSP после disconnect. Это не full SFU restart и не имитация packet loss медиа.

`test/build-reference.mjs` — необязательная сборка старого снимка для A/B; `REFERENCE_DIR` должен указывать на предоставленные отдельно предыдущие исходники frontend. Старый снимок не включён в этот архив. Отчёт содержит сравнение с версией от 8 октября при одинаковых библиотеках/сервере.
