# Concord — история чата, вложения и блокировки: 16 октября 2026

Продолжение [проверки звонков и сессий](VERIFICATION-2026-10-16.md). Найдены и исправлены дополнительные воспроизводимые ошибки. CSS не менялся: сборка по-прежнему содержит `main-TZFOKFC5.css`.

## Исправления

- Запоздавшая загрузка истории больше не заменяет более свежую страницу. Во время запроса сохраняются пришедшие сообщения, изменения, удаления и реакции. Пагинация объединяет совпадающие ID без дублей; ответ от прежнего окна после reconnect/logout не восстанавливает сброшенный кеш.
- Ошибка сети при загрузке новых страниц не считается концом истории. Уже видимые сообщения остаются на месте, повторная загрузка разрешена. Поздний ответ отправки не откатывает `lastMessageId` и указатель прочтения.
- Неудачное подтверждение прочтения можно повторить; откат локальной оптимистической отметки не перезаписывает более новое gateway-событие. Чужое новое сообщение в открытом канале больше не отмечается прочитанным без учёта позиции списка. Переход к старому результату поиска не сбрасывает непрочитанное целиком.
- Backend возвращает фактически сохранённый указатель прочтения, пересчитывает только оставшиеся упоминания и ограничивает указатель существующей историей. «Отметить непрочитанным» согласует счётчик в БД и realtime-событии. Изменение счётчиков сообщений, включая @everyone, выполняется в транзакции; explicit mention вместе с @everyone считается один раз.
- Удаление файла, успешная отправка и уход из канала освобождают его object URL. Незавершённая загрузка прерывается при уходе; поздний callback не возвращает её в интерфейс. Ошибка отправки сохраняет вложения и не затирает текст, набранный во время запроса. Повторная отправка до завершения предыдущей блокируется.
- Черновики привязаны к аккаунту, каналу и ветке: после logout/login другого пользователя текст прежнего аккаунта не появляется. Переключение ветки создаёт отдельный composer; нестабильный callback закрытия больше не перезапускает загрузку ветки при каждом родительском обновлении.
- Редактирование или закрепление сообщения не переносит чужой флаг реакции `me` на всех участников. Ветки получают live-обновления реакций. Для участников за пределами первых 20 ID событие содержит точное состояние реакции самого автора действия. Лимит 20 разных эмодзи разрешает присоединиться к существующему; конкурентные добавления сериализованы по сообщению.
- Блокировка в любую сторону запрещает ring/accept личного звонка. Pending ring от заблокированного пользователя не восстанавливается при повторном входе. После разблокировки звонки снова доступны.

Восемь исходных сценариев состояния чата сначала упали на прежнем коде, затем прошли после исправлений. Браузер воспроизвёл неосвобождённый preview; тесты также подтвердили возможность звонка после блокировки до исправления. Дополнительные проверки покрывают поздний read ACK, 21 одновременную новую реакцию при лимите 20 и единый счётчик explicit mention + @everyone.

Локальный стенд: Windows, Node 24.19.0, Chrome 155.0.8059.40, PostgreSQL 16.15, Redis 5.0.14.1, LiveKit 1.13.9. Использованы отдельные тестовые базы, Redis DB и локальная почта. Логи/JSON: [docs/results](results/), файлы `*-polish.*`. Скриншоты остаются локально. Секреты и пользовательские данные в результаты не включались.

GitHub Actions запускает типы, тесты, сборки и отдельный Chromium WebRTC harness на чистом Ubuntu. [Статус конкретного коммита](https://github.com/Error52/concord/actions/workflows/ci.yml) следует смотреть у соответствующего запуска.
