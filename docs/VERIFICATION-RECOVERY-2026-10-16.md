# Concord — восстановление данных и завершение звонков: 16 октября 2026

Дополнение к [предыдущему проходу чата](VERIFICATION-CHAT-2026-10-16.md). Найдены дополнительные воспроизводимые сбои. Оформление сохранено, CSS остался `main-TZFOKFC5.css`.

## Исправления

- Старый ответ поиска сообщений или быстрого поиска больше не заменяет результаты нового запроса и не возвращает их после очистки строки. Устаревшие success/error/finally не меняют loading/error нового запроса. Такие же проверки владения запросом добавлены в обзор серверов и preview приглашения; ошибка старого инвайта не перекрывает новый действующий.
- Ветка сохраняет события, пришедшие во время загрузки snapshot: новые ответы, изменения, удаления и реакции воспроизводятся по порядку поверх ответа API. После gateway reconnect открытая ветка запрашивает актуальные данные. Закрытая ветка игнорирует поздний ответ; удалённый родитель не возвращается. События других каналов не копятся в её очереди, а несвязанные сообщения сохраняют прежний объект состояния без лишнего рендера.
- Ошибка read-запроса при открытии уведомлений обрабатывается и показывается пользователю. Read/clear применяют только фактически изменённые сервером IDs и уменьшают счётчик на точное число непрочитанных. Приход нового уведомления после выполнения серверной операции и до ответа клиенту больше не приводит к его удалению/ложному прочтению. Свежий ready snapshot имеет приоритет над старым ответом операции.
- Ошибка закрытия DM больше не прячет диалог локально. Успешное закрытие активной переписки возвращает к друзьям. Новое входящее сообщение, восстановившее диалог во время ожидания ответа, имеет приоритет над старым close-запросом.
- Удаление голосового канала/сервера сначала отправляет активным участникам отключение, вызывает SFU RemoveParticipant и очищает occupancy. История выхода записывается до удаления каналов. Отключение привязано к ожидаемому каналу: старое событие от другого звонка не останавливает новый захват.

## Обновление

Новых миграций нет. Backend и frontend обновить вместе по [QUICKSTART](../QUICKSTART.md). `POST /api/notifications/read` и `DELETE /api/notifications` теперь отвечают **200 JSON `{ids, unreadChanged}`** вместо 204: IDs относятся только к действительно изменённым записям текущего пользователя; повторное чтение уже прочитанного даёт пустой список и ноль.

Удаление участников SFU остаётся best-effort при недоступности его административного API; подтверждённый браузерный сценарий выполнялся с доступным локальным SFU. Физический второй клиент, WAN/TURN, Safari/телефоны, внешний SMTP и полный Docker-стек требуют отдельных проверок. Результаты не дают оснований объявить весь сервис свободным от ошибок.
