# Concord — установка, почта и медиа: 16 октября 2026

Проверен внешний аудит и ошибка установки с тайм-аутами registry.npmjs.org. Сохранены предыдущие исправления. Цвета, шрифты и компоненты не переделывались; единственное изменение CSS — ограничения мобильного заголовка «Друзья», чтобы заголовок не сжимался до одной буквы и вкладки прокручивались внутри строки. CSS новой сборки: `main-5WAF5OHU.css`.

## Исправления

| Область | Результат |
| --- | --- |
| Docker / npm | Pinned pnpm и frozen lockfile сохранены. Кэш пакетов переживает повтор сборки; четыре параллельных запроса, пять повторов, тайм-аут запроса 300 секунд. Настраиваемый доверенный NPM_REGISTRY передаётся и Corepack, и установке. TLS, package integrity и supply-chain проверки не отключены. Зависимости не устанавливаются смешением npm и pnpm. |
| Почта на VPS | Явно пустой SMTP_HOST больше не превращается в отсутствующий Mailpit. Публичный установщик и backend останавливаются с инструкцией настроить реальный SMTP до того, как появятся застрявшие регистрации. LAN-демопочта продолжает работать. Настоящий SMTP требует данных выбранного провайдера; внешняя доставка из этого окружения не измерялась. |
| SMTP | Ограничено ожидание подключения и обоих TLS-рукопожатий; закрытие сокета завершает promise. AUTH PLAIN запрещён без TLS/STARTTLS. Буферы и ответы до STARTTLS не используются после него. Падение/тайм-аут освобождает почтового worker для последующих попыток. |
| Секретные ссылки в очереди | Новые тела писем зашифрованы AES-256-GCM. До старта HTTP старые строки очереди переводятся в зашифрованный формат. Доставленные тела удаляются; действующее демописьмо сохраняется зашифрованным до использования/истечения. Старые бэкапы автоматически не переписываются. |
| Права администратора | PLATFORM_ADMIN_EMAILS применяется после настоящего SMTP-подтверждения. Демо-подтверждение и перезапуск сервера не повышают такой аккаунт. Первый админ новой установки и явно выданные права сохранены. Миграция 005 хранит признак настоящей проверки отдельно. |
| Голосовые права | Правки, назначения и удаление ролей сразу пересчитывают CONNECT/SPEAK/VIDEO активного участника SFU. Обновления сериализованы по участнику. Старый токен перепроверяется в webhook и периодической сверке; сверка находит комнаты, отсутствующие в Redis. Новые join-токены действуют пять минут. При недоступном SFU удаление остаётся best effort, это не гарантия мгновенного отзыва при сетевой аварии. |
| Захват и модерация | Отзыв SPEAK останавливает исходный микрофон и AudioContext; возврат права возобновляет передачу. Одновременный self-mute не перетирается серверным мутом. Старый выход из комнаты не удаляет уже новое состояние Redis. |
| Демонстрация | Motion-профили используют maintain-framerate; detail-профиль сохраняет maintain-resolution. H.264 имеет VP8 backup с предпочтением перехода на один кодек. Старые buffered unpublish-события полного reconnect не останавливают уже восстановленные публикации. |
| Инвайты | Бан проверяется до расхода приглашения. Счётчик и вступление выполняются в одной транзакции. Повторные запросы того же участника идемпотентны; за одно место могут конкурировать разные пользователи без превышения лимита. |
| Почта / закрепления | Устранён воспроизведённый deadlock confirm/resend. Лимит 50 закреплений проверяется атомарно; повторное закрепление существующего pin при заполненном лимите успешно. |
| Клиентский чат | Быстрые отправки выстраиваются в очередь, файлы не прикладываются повторно. Неудачная отправка сохраняет черновик и вложения. Поиск сохраняет страницу во время следующей загрузки и игнорирует старые ответы. |
| Серверы / закладки / картинки | Поздняя загрузка не возвращает удалённый сервер. Закладки можно повторно загрузить после ошибки, ошибка удаления не прячет элемент. Изображения в ветке открываются в том же просмотрщике, что и в канале. После отказа старой media cookie клиент обновляет собственную сессию и один раз повторяет загрузку; сервер не принимает старую cookie в обход отзыва сессии. |
| Уведомления | Read/clear доставляются всем подключённым устройствам пользователя. Mutation ID исключает повторное уменьшение счётчика через HTTP и gateway; новые уведомления сохраняются. |
| Развёртывание | Медиа-порты установщика/firewall берутся из конфигурации. Публичный режим выключает loopback. dev.mjs создаёт/обновляет .env с правами 0600 на Unix. Windows использует Node из PATH/CONCORD_NODE; LAN JSON содержит медиа-порты для firewall. Для Mailpit на Linux указана установка release-бинарника. |
| Существующий PostgreSQL | Compose требует явный POSTGRES_IMAGE; установщик сохраняет образ имеющегося контейнера и не меняет libc незаметно. Добавлены инструкция миграции и отдельный helper с backup → REINDEX → refresh collation. Он не запускается автоматически и не удаляет тома. Существующая база пользователя не переиндексировалась. |

## Проверки

- Backend: **68/68**, реальные отдельные PostgreSQL/Redis; среди регрессий — TLS timeout/STARTTLS injection, шифрование и очистка очереди, demo-admin spoof, инвайты, роль активного звонка, пропущенный webhook и два устройства уведомлений.
- Frontend: **67/67**; проверки типов и production-сборки обеих частей прошли.
- Chrome: **8 edge cases**, **11 recovery cases**, **4 composer cases**, **17 UI E2E**, **121 layout check**. Отдельно прошли регистрация/повтор письма/сброс пароля/повтор загрузки chunk и настоящий WebRTC loopback с микрофоном/AudioWorklet. Мобильные проверки включают wheel/touch scroll и доступность диалогов; подробные результаты в `docs/results/*-audit.*`.
- Docker Compose и обе Docker-сборки включены в отдельную задачу GitHub Actions `containers`. Локально Docker недоступен; итоговый статус контейнеров — в [GitHub Actions](https://github.com/Error52/concord/actions/workflows/ci.yml).
- Локальный deployment-тест сохраняет секреты и медиа-порты при LAN update и проверяет права .env. Проверка Compose выполняется на Linux CI. PowerShell-шаблоны проверены парсером, Bash-синтаксис проверяется в CI.

Полные логи и JSON сохранены в `docs/results/`. До публикации исключаются configured secrets, runtime, базы, env-файлы, ключи и скриншоты прогонов; MANIFEST.sha256 пересчитывается. Наставления для внешних ассистентов не добавлялись.

## Медиапрогон

Chrome **155.0.8059.80**, Node **24.19.0**, Windows, два браузерных контекста на одной машине. Источник — движущийся canvas 1920×1080/60 и отдельные тестовые тоны 220/880 Hz в левом/правом каналах. Это не игра и не измерение на слабом ПК или через интернет.

| Сценарий | Результат |
| --- | --- |
| H.264 после полного reconnect | 1920×1080, первый кадр до fault injection **377 мс**, **52.33 fps**, median **51.7 мс**, p95 **54.9 мс**, 175 корректных timestamp samples. |
| Получатель согласовывает только VP8 | Реально декодированы движущиеся VP8-кадры со стереозвуком. Native adaptation снизила разрешение до **640×360**, сохранив **53.93 fps**; median **47.5 мс**, p95 **51.6 мс**. Этот прогон доказывает совместимость, а не HD-качество VP8 на любой машине. |

Полное переподключение, восстановление сигналинга, серверный mute/unmute с ростом реальных RTP bytes, сохранение self-mute, смена источника, повтор после отказа доступа, отмена отложенного захвата, быстрый повтор камеры/демонстрации и освобождение захвата при выходе прошли без необработанных ошибок. После полного reconnect проверялись актуальные live publications и рост новых декодированных кадров, а не только наличие последнего кадра в DOM. Стереоканалы оставались разделены.

Для fault injection используется только `node test/build-media-harness.mjs`; этот dist открывает инспекцию движка для теста. Перед публикацией восстановлена обычная `node build.mjs`, тестовый доступ в production отсутствует.

## Повтор проверки

Использовать отдельную seeded UI-среду; скрипты создают тестовые аккаунты/сообщения. Задать BASE_URL, MAILBOX_URL и при необходимости CHROMIUM_PATH. `npm run test:edges`, `npm run test:recovery`, `npm run test:composer`, `npm run test:e2e`, `npm run test:responsive`, `npm run test:auth` и `npm run test:webrtc` запускают соответствующие проверки. Не очищать rate limits рабочей установки; локальный оркестратор сбрасывал только `rl:*` в отдельном QA Redis DB 2 между независимыми UI-пакетами.

Для полного media fault injection: построить test/build-media-harness.mjs, запустить media-benchmark.mjs с EXPECT_FULL_RECONNECT=1, затем восстановить production build. Отдельный BENCH_ONLY=1/FORCE_VP8_RECEIVER=1 проверяет SDP без H.264. Обычный production `npm run test:media` не использует тестовую инспекцию движка.

Перед обновлением существующего сервера прочитать [UPGRADING.md](UPGRADING.md). Для LAN после `git pull --ff-only` повторить `sudo ./scripts/install-server.sh --lan`; уже скачанные пакеты переиспользуются. Рабочие env/данные/тома сохраняются.
