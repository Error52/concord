# Concord — исправления после проверки регрессий

Повторная проверка 17 октября 2026 после `c87c6af`. Предыдущие найденные ошибки уже исправлены; этот проход проверяет, не оставили ли изменения новые гонки. Дизайн и CSS сохранены: production CSS — `main-5WAF5OHU.css`.

## Исправления

| Воспроизведение | Изменение и контроль соседнего поведения |
| --- | --- |
| Две отправки A и B сохраняются, но обе теряют HTTP-ответ; ошибка B стирает nonce A | Cache хранит ключи для разных payload одного редактора отдельно. Повтор A возвращает исходное сообщение, сохраняя ровно одно A и одно B. Общий лимит — 128 записей; успешная отправка удаляет только соответствующий nonce. |
| Caller остаётся в SFU, ring истекает, затем начинается новый вызов | Предыдущий долговечный marker сохраняется как пропущенный до замены новым. Уже отвеченная медиасессия не превращается в пропущенный вызов. |
| Accept пришёл раньше фактического подключения к медиа, а caller успел выйти | Accept больше не удаляет marker до завершения медиасессии. Неудавшийся медиавход оставляет одну запись о пропущенном; реальное подключение двух участников сохраняет запись завершённого звонка. |
| Старая вкладка того же caller отправляет `call:end` для нового вызова | Сервер сохраняет действующий participant SID в ring, клиент передаёт SID при отключении. Старый или отсутствующий SID не отменяет новый защищённый ring. Legacy ring без SID продолжает работать. Дополнительно проверены чужой пользователь, самопринятие, чужая отмена и старый ring ID. |
| Logout завершает отзыв между первой проверкой WebSocket и его добавлением в индекс сессий | Сразу после индексирования сервер повторно проверяет активность сессии. Отзыв до индекса ловит эта проверка, после индекса — подписчик revoke. Отозванное соединение закрывается 4003 без `ready`. |
| Voice admission прочитал активную семью, logout завершился до записи Redis presence | Допуск медиа и изменение сессий используют один per-user advisory lock. Либо logout видит опубликованное присутствие и снимает его, либо admission видит уже отозванную семью. Проверены оба порядка исполнения. |

Baseline-проверки выполнялись на изолированных копиях: две потери call history, неверный nonce, потерянный WS revoke и оба порядка voice/logout воспроизведены до исправления. Такие копии не входят в приложение.

Изменения локальны: дополнительный session lookup выполняется при установлении gateway, а не на каждом speaking/typing событии; пользовательские данные и схема БД остаются прежними. Общая блокировка допуска медиа берётся перед voice-state lock, чтобы не ввести обратный порядок ожидания.

## Проверки и границы

Полный набор включает прежние проверки регистрации, 2FA, refresh/reset, ролей, файлов, сообщений, друзей и звонков, а также новые негативные сценарии. Результаты этого прогона публикуются в [results](results) с суффиксом `-regression`.

- Backend **139/139**, frontend **89/89**. Все прежние 128 backend и 86 frontend тестов сохранены; новые случаи проверяют и запрещённые, и разрешённые действия. TypeScript и production build проходят.
- Composer **7/7**, полный браузерный E2E **17/17**, реальные DM звонки **4/4**: отмена, отклонение с последующим выходом, разговор до последнего ухода и поздняя отмена из старой вкладки. Проверяются реальные строки истории и WebSocket/SFU события. Ошибок браузера нет.
- Начальный voice E2E остановился на ICE до `participant_joined`. Изолированный SFU рекламировал loopback-адрес; после выбора адреса активного локального интерфейса полный прогон прошёл без изменения приложения и таймаутов. Настройки установки Concord не менялись. Сигнализация и медиа используют отдельные порты, как описано в [справочнике LiveKit](https://docs.livekit.io/transport/self-hosting/ports-firewall/).
- Повторный H.264 media lifecycle: **1920×1080, 53,58 fps**, median задержки картинки **49,2 мс**, p95 **53,2 мс** (179 измерений). Стереоканалы разделены; полный SFU reconnect восстанавливает живые микрофон, камеру, экран и новые декодированные HD-кадры. Server mute/unmute, смена источника, отказ/возврат разрешения, отмена захвата и cleanup проходят. Тест использует canvas 1080p60 и тоны 220/880 Гц на одном компьютере. Диагностическая сборка заменена штатной production-сборкой после теста.

Это не атомарная транзакция с внешним SFU: ранее выданный grant может кратко достигнуть SFU до обработки webhook. Проверка admission закрывает найденную гонку сохранения presence с logout; отказ SFU/Redis всё ещё не даёт гарантированной мгновенной доставки событий. Переходное legacy-окно и требования обновления обеих частей описаны в [UPGRADING.md](UPGRADING.md).

Проверки localhost не заменяют измерения на физическом слабом ПК и между устройствами LAN/WAN. Ни один тестовый набор не доказывает отсутствие всех возможных ошибок.
