# Concord — надёжность звонков, сессий и почты: 16 октября 2026

Исправлены воспроизводимые сбои в существующем интерфейсе. Цвета, шрифты, расположение элементов и стили не менялись: CSS сборки по-прежнему `main-TZFOKFC5.css`.

## Изменения

- Gateway восстанавливается после временной ошибки обновления сессии и пропавшего heartbeat ACK. Повторный запуск не создаёт лишние соединения; callbacks старого сокета не закрывают новое соединение и не сбрасывают его таймеры. Offline/online и logout во время refresh проверены отдельно.
- Поздний ответ refresh не возвращает пользователя после выхода и не заменяет новый аккаунт. Запросы и загрузки от прежнего аккаунта отклоняются при смене сессии; отмена загрузки во время refresh сразу завершает promise и не отправляет файл повторно. Сетевые ошибки повторного запроса получают обычный `NETWORK`.
- После быстрого disconnect/rejoin во время разрешения камеры или экрана новый захват запускается нормально. Поздний результат старой операции освобождает свои ресурсы и не сбрасывает состояние нового звонка. Недоступный сохранённый микрофон переключается на устройство по умолчанию, включая ошибку `NotFoundError`.
- Статистика рассчитывает приращения отдельно для каждой RTP-дорожки. Подключение/выход участника, смена SSRC и перезапуск счётчиков не создают ложные скачки битрейта и потерь. ID codec/transport разрешаются отдельно для publisher/subscriber.
- Разрешение VIDEO управляет камерой, экраном и звуком экрана. При снятии серверного mute/deaf backend заново учитывает CONNECT/SPEAK/VIDEO участника. Если доступных источников нет, `canPublish=false`; пустой список источников при разрешённой публикации больше не открывает лишний доступ.
- Почтовая очередь учитывает назначение, хеш токена и его исходный срок. Просроченные, использованные и заменённые verification/reset ссылки не выбираются для повторной отправки после сбоя SMTP. Смена пароля аннулирует незавершённые reset-токены. Миграция `004_mail_validity.sql` сохраняет сроки старых писем; неизвестный auth-токен считается просроченным.
- GitHub Actions проверяет frontend/backend на push и pull request с отдельными PostgreSQL/Redis. После установки из lockfile команды используют `npm run`, чтобы pnpm не пытался повторно менять дерево зависимостей перед запуском. Docker test target включает все файлы `*.test.ts`.

Два браузера на одной Windows-машине, синтетический движущийся canvas **1920×1080 / 60 fps** и stereo-тоны 220/880 Hz, профиль Auto. Это передача через локальный LiveKit, без захвата пользовательского рабочего стола.

|---|---|

Счётчик fps за короткое окно отличается от среднего числа показанных кадров за весь интервал. Этот замер не подтверждает постоянные 60 fps. Он не измеряет задержку голоса mouth-to-ear, физического монитора, реальной игры, слабого ПК или Wi-Fi между двумя устройствами.

## Обновление и границы

Нужны все миграции по порядку, включая `004_mail_validity.sql`; штатный backend применяет их перед обслуживанием запросов. После обновления перезапустить backend и собрать frontend по [QUICKSTART](../QUICKSTART.md). В пользовательском окружении сначала сохранить резервную копию БД.

SMTP обеспечивает доставку как минимум один раз: авария после принятия письма SMTP может привести к повтору. Уже отправленное или находящееся в отправке письмо отозвать нельзя; сервер всё равно проверяет действительность ссылки при использовании.

Проверки выполнены локально и в CI, без физического второго устройства. Полный Docker-стек, внешний SMTP/TLS, Safari/телефоны, WAN/TURN между NAT и нагрузка настоящей игры на слабом железе требуют отдельных замеров. GitHub хранит исходники; постоянно работающий публичный сервер этим обновлением не развёрнут.
