## Исправления

- Режим `secret-word` активирует аккаунт без SMTP, отдельно от подтверждения email. Вход принимает имя/email. Старые подтверждённые пользователи и администраторы сохраняют доступ; незавершённые аккаунты задают первое слово после проверки пароля.
- Восстановление меняет пароль и слово, закрывает все сеансы/медиа, сохраняет и проверяет 2FA. Ограничения IP/аккаунта отклоняют запрос при ошибке Redis. Параллельные восстановления дают одного победителя. Смена роли или отзыв сеанса во время операции не обходят защиту.
- Для администратора публичное восстановление по слову запрещено. Операторский CLI читает пароль скрыто или из ограниченного JSON stdin, отзывает сеансы и пишет аудит без секретов.
- Форма сохраняет подтверждённый результат установки слова даже при временном сбое обновления сеанса; при повторном открытии правильно требует уже установленное слово.
- DM открывается из подтверждённого HTTP-ответа при потере события WebSocket. Старый snapshot не откатывает указатель последнего сообщения.
- Добавлена запись голосовых: поддерживаемый аудиоформат, отмена, предел 5 минут/25 МБ, освобождение микрофона при смене канала. Audio-only WebM/MP4 распознаются по контейнеру и отображаются аудиоплеером с перемоткой.
- Без API-ключа работает каталог из шести оригинальных локальных GIF (CC0). Поиск, категории и отправка независимы от внешнего провайдера. Настроенные Giphy/Tenor сохраняются, `none` явно отключает GIF.
- Микрофон/камера/динамики освобождаются при закрытии настроек, позднем разрешении, отказе воспроизведения и зависшей загрузке AudioWorklet.

После обновления повторены полный UI-прогон 17/17, голосовые/GIF 6/6 и восстановление отдельного синтетического аккаунта: неверное слово отклонено, оба секрета изменены, старые пароль и сеанс не работают, новый вход активен без ложного подтверждения email. Вход существующего администратора и открытие админ-панели проверены без изменения его пароля/прав. Все три задания GitHub CI прошли.

Одновременно с демонстрацией выполнен ограниченный тест: три ступени по 15 секунд, 2/8/20 GET в секунду и 1/4/8 WebSocket, два тестовых аккаунта. Выполнено 442 запроса, все 200, восемь плановых слотов пропущены из-за занятых клиентских запросов на второй ступени. На пике 300/300 запросов, p50/p95 87,06/154,62 мс, чтение сообщений p95 120,17 мс, ошибок HTTP/WS нет. У heartbeat были скачки до 2,96 с (p95 2,10 с); повторная короткая проверка отдельно от браузерных задач дала на пике HTTP p95 97,38 мс, heartbeat p95 355,27 мс. Эти измерения не позволяют приписать скачки исключительно серверу или считать их устранёнными.

В интервале пиковой нагрузки демка сохранила 1920×1080, 53,3 кадра/с, p95 задержки кадра 256,3 мс через интернет. Стереоканалы разделены, захват завершён чисто. У каждого из двух аудиопотоков за измеренный интервал потерян один пакет из примерно 502; компенсация потерь составила 0 и 888 из 481 920 аудиосэмплов. Это не нулевые потери, но длительного выпадения передачи тест не обнаружил.

21 выборка ресурсов: CPU хоста максимум 45,04%, backend 38,12%, SFU 18,43%; минимум доступной памяти 1119,2 МиБ. Это проверка небольшой группы и ограниченной нагрузки, без оценки максимальной вместимости SFU. После проверки удалены четыре временных аккаунта, два тестовых сообщества и пять файлов; действующие администраторы и их секреты не изменены.
