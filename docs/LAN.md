# Concord в локальной сети — 13 октября 2026

Текущий Windows-сервер: **https://192.168.1.249:8443**. Одна PostgreSQL-база хранит аккаунты, серверы, сообщения и вложения всех участников. Redis обслуживает присутствие и события; LiveKit передаёт голос и демонстрацию. Дизайн сохранён.

## Подключить установленную Windows-копию

Сайт и семь процессов уже запущены. Системные запросы на установку сертификата и изменение брандмауэра были отменены, поэтому доступ с физически другого устройства ещё не подтверждён.

1. На компьютере-сервере открыть `outputs/Enable-Concord-LAN.cmd` и разрешить UAC Windows. Скрипт открывает только TCP 8443, TCP 7881 и UDP 7882, только на интерфейсе Wi-Fi, на локальном IP 192.168.1.249 и для подсети 192.168.1.0/24. Базу, Redis, SMTP и общий почтовый интерфейс он не публикует. Профиль Wi-Fi остаётся прежним; брандмауэр не отключается.
2. На каждом Windows-клиенте, включая сервер, распаковать `concord-lan-client.zip`, открыть `Install-Concord-Certificate.cmd` и подтвердить сертификат **Concord LAN — 2026 ECC Root**. Установка относится к текущему пользователю. Перезапустить браузер.
3. Подключиться к той же Wi-Fi/локальной сети и открыть **https://192.168.1.249:8443**. Зарегистрироваться или войти. Для теста есть Alice/Bob/Carol/Dave, `имя@concord.local`, пароль `demo12345`.

Письма в этой выбранной пользователем демоверсии остаются на сервере. На карточке подтверждения есть **«Открыть письмо в демопочте»**: только после входа с паролем, только собственное действующее письмо подтверждения. Общий Mailpit доступен лишь владельцу на http://localhost:58025. Чужие письма и ссылки сброса через этот endpoint получить нельзя. Это демонстрация потока регистрации, без проверки владения настоящим email. Реальную доставку включает собственный SMTP при `DEMO_MAILBOX=false`.

Запуск/остановка: `Start-Concord.cmd` / `Stop-Concord.cmd`. Режим LAN сохраняется. Если DHCP изменил IP сервера, `Start-Concord-LAN.cmd` остановит сервисы и определит текущий адрес; затем повторить Enable для новых узких правил и отправить друзьям новый адрес. Корневой сертификат хранится постоянно и не меняется при обычном перезапуске. Приватные ключи CA остаются в `work/local-data/caddy`, друзьям передаётся только публичный root.crt.

Отмена правил: `Disable-Concord-LAN.cmd`. Данные не удаляются. Если сайт после включения правил недоступен со второго устройства, проверить, что это одна сеть без изоляции клиентов/гостевого Wi-Fi. Физические вторые устройства здесь не использовались.

## Телефоны

Передать публичный `Concord-LAN-root.crt` на устройство и установить как доверенный CA. Для iPhone/iPad после установки профиля также включить доверие корню в Настройки → Основные → Об этом устройстве → Доверие сертификатам: [инструкция Apple](https://support.apple.com/en-us/102390). Для Android расположение настройки зависит от производителя: [инструкция Google](https://support.google.com/pixelphone/answer/2844832/add-amp-remove-certificates). Переход через предупреждение браузера не заменяет доверие сертификату для всех возможностей микрофона/демонстрации. Реальные Safari/телефоны здесь не проверялись; поддержка системного звука и screen capture зависит от браузера и ОС.

## Чистая копия через Docker

Нужны Node 24 и Docker Compose v2. В корне исходников:

```sh
node scripts/dev.mjs lan 192.168.1.20
```

Подставить IP своей машины. Команда создаёт новые секреты лишь при отсутствии `.env`, затем меняет только LAN-настройки: HTTPS, Secure cookies, LiveKit/TURN IP, профили https+dev и личную демопочту. Существующие секреты и volumes сохраняются. Вариант `lan-config <IP>` только готовит конфигурацию без запуска Docker.

После запуска извлечь публичный CA, доверить на клиентах:

```sh
docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt Concord-LAN-root.crt
```

Разрешить TCP 8443, указанные в `.env` LIVEKIT_TCP_PORT/LIVEKIT_UDP_PORT и, при использовании TURN, его порты в локальном брандмауэре. Новый dev.mjs использует media TCP7981/UDP7982, существующая установленная Windows-копия — TCP7881/UDP7882. Docker здесь отсутствует: конфигурация и сохранение секретов проверены, запуск контейнеров требует проверки принимающей машиной.

Публичное размещение с доменом отличается: профиль server, публичный сертификат, настоящий SMTP и выключенная демопочта. Сетевой адрес из этого отчёта относится к LAN и не является адресом сайта в интернете.

## Повторить проверки

В `frontend`, на отдельном seeded тестовом стеке:

```powershell
$env:BASE_URL='https://192.168.1.20:8443'
$env:LAN_CA_FILE='C:\path\Concord-LAN-root.crt'
$env:LAN_DIR='test/results/lan'
node test/lan.mjs
$env:BENCH_ONLY='1'
$env:MEDIA_DIR='test/results/media-lan'
node test/media-benchmark.mjs
```

LAN smoke создаёт один тестовый аккаунт и отправляет сообщение Alice→Bob. TLS проверяется Node с конкретным CA, после чего изолированный Chrome доверяет проверенному ключу серверного сертификата. Хранилище сертификатов пользователя тесты не меняют. Медиа — synthetic canvas/tones, без захвата рабочего стола.

Локальная CA и требования доверия: [официальная документация Caddy](https://caddyserver.com/docs/automatic-https#local-https).
