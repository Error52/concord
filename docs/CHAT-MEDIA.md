# Голосовые сообщения и локальные GIF

В строке сообщения есть кнопка микрофона в существующем стиле интерфейса. Запись использует выбранный микрофон и настройки подавления шума/эха. Если сохранённое устройство отключено, браузер один раз пробует устройство по умолчанию. Нужен HTTPS либо localhost и разрешение на микрофон.

Кнопка остановки превращает запись в обычное вложение: перед отправкой её можно удалить или добавить текст. Отправка происходит обычной кнопкой сообщения. Отмена, смена канала и закрытие редактора прекращают собственные захваты; поздний ответ браузерного разрешения не добавляет файл. Ограничения — пять минут и 25 МиБ; лимит HTTP uploads сервера также продолжает действовать.

Предпочтительный формат — Opus/WebM, затем Opus/Ogg, затем MP4, если браузер поддерживает его. Запись с неизвестным форматом показывает ошибку. Backend отличает аудио от видео по ограниченному разбору WebM Tracks / MP4 track handler metadata; клиентский Content-Type не определяет тип вложения. Аудио воспроизводится встроенным HTML audio player и поддерживает Range-запросы. Реальное качество и поддержка форматов зависят от браузера; unit-проверка MIME fallback не заменяет проверку записи/декодирования в конкретном браузере.

## Каталог GIF без внешнего ключа

`GIF_PROVIDER=local` включает шесть небольших оригинальных анимированных реакций: приветствие, сердце, смех, подтверждение, звезду и огонь. При `giphy`/`tenor` с пустым `GIF_API_KEY` используется тот же локальный каталог. Настроенный внешний ключ сохраняет выбранный внешний провайдер; `GIF_PROVIDER=none` явно отключает новые GIF.

Локальный поиск работает по названиям и русским/английским тегам. Это конечный каталог реакций, без интернет-поиска по фильмам, мемам и знаменитостям. Известные файлы доступны анонимно по `/api/gifs/local/<id>.gif` и не содержат пользовательских данных. Ссылки каталога абсолютные и строятся из `APP_URL`, поэтому эта настройка должна совпадать с публичным HTTPS origin. В сообщениях разрешаются только точные URL известных реакций; произвольные локальные пути и внешние preview не проходят проверку.

Анимации созданы специально для Concord из простых геометрических фигур. Только эти шесть анимаций передаются по CC0 1.0; это не меняет лицензию остальных файлов проекта. Они хранятся как Base64 в `backend/src/services/gif/localCatalog.ts`, поэтому production не нуждается в Pillow и дополнительных бинарных assets. Для воспроизводимой генерации разработчику нужен Python с Pillow:

```bash
python scripts/generate-local-gifs.py
```

Проверка двух браузерных клиентов на тестовой установке с демо-аккаунтами:

```bash
cd frontend
BASE_URL=http://localhost:5181 node test/message-features.mjs
```

Используется синтетический микрофон Chrome; тест записывает, загружает и декодирует настоящее аудио, проверяет отмену захвата и получает анимированный GIF на втором клиенте. Он создаёт только тестовые сообщения в указанной установке; запускайте его на выделенном QA стенде.
