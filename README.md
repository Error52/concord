# Concord

Веб-мессенджер: серверы и каналы, общий backend, регистрация и вход, личные сообщения, голос, видео и демонстрация экрана со stereo-звуком. React/TypeScript, Node.js, PostgreSQL, Redis, LiveKit.

## Быстрый запуск

Нужны Node.js 24 и Docker с Compose v2.

```sh
git clone https://github.com/Error52/concord.git
cd concord
node scripts/dev.mjs up
```

Открыть http://localhost:8080. Команда создаёт `.env` со случайными секретами, сохраняет уже существующие настройки и данные. Первый запуск скачивает зависимости и Docker-образы.

Для локальной сети: `node scripts/dev.mjs lan <IP-вашего-компьютера>`. Для микрофона и демонстрации на других устройствах нужно доверить LAN-сертификату; см. [LAN.md](docs/LAN.md).

Демо: `alice@concord.local` / `demo12345`, также `bob`, `carol`, `dave`. Для новых аккаунтов есть подтверждение почты; в LAN-демо письмо открывается в собственном аккаунте. Для настоящей отправки настроить SMTP и выключить `DEMO_MAILBOX`.

**На сервере в интернете (чтобы все заходили по адресу):**

```bash

```

Если Docker Hub недоступен из вашей сети, добавьте зеркало в `/etc/docker/daemon.json`: `{ "registry-mirrors": ["https://mirror.gcr.io"] }`, затем `sudo systemctl restart docker`.

```bash
./scripts/setup.sh          # создаёт .env со случайными секретами (macOS и Linux)
make up                     # = docker compose up --build -d
# → http://localhost   (демо: alice@concord.local / demo12345, также bob, carol, dave)
```

## Архитектура

```
 Browser (React + TS)
   │  REST  /api/*            ┌──────────────┐
   ├──────────────────────────▶              │──▶ PostgreSQL  (данные, полнотекстовый поиск)
   │  WebSocket /api/gateway  │   backend    │──▶ Redis       (presence, rate limit, voice state,
   ├──────────────────────────▶  Node.js/TS  │                 pub/sub между инстансами)
   │                          │              │──▶ том uploads / S3 (файлы, аватары, баннеры)
   │                          └──────▲───────┘
   │                                 │ webhooks (подписанные JWT) + RoomService API
   │  WebSocket /livekit (сигналинг) │
   ├──────────────────────────▶  LiveKit SFU  ◀──── UDP 7882 / TCP 7881 (медиа)
   │                                 │
   └── ICE: host / STUN / TURN ──▶ coturn :3478 (relay при симметричном NAT)

 nginx (контейнер frontend) — единая точка входа http://localhost: статика SPA + /api + /livekit
```

### Почему эти технологии

| Решение | Выбор | Почему |
|---|---|---|
| SFU | **LiveKit** (а не mediasoup) | Готовый SFU: simulcast/dynacast, серверный audio level и active speaker, ICE restart + resume и переподключение в клиенте, вебхуки о входе/выходе, управление правами участника (используется для серверного мута). mediasoup — библиотека: сигналинг, транспорты, recovery и масштабирование пришлось бы писать самим. |
| Авторизация | Короткий **access JWT** (15 мин, в памяти) + **refresh-токен в httpOnly SameSite=Strict cookie** с ротацией | Access-токен не лежит в localStorage (XSS не украдёт сессию надолго), refresh одноразовый: повторное использование старого токена = кража → отзывается вся «семья» сессий. CSRF закрыт заголовком `X-Requested-With` + проверкой Origin на cookie-эндпоинтах. |
| Пароли | **scrypt** (N=2¹⁵, r=8) | Memory-hard KDF из стандартной библиотеки Node, параметры хранятся в хеше. |
| Realtime | Свой WebSocket-gateway + Redis pub/sub | События адресуются пользователям/серверам; несколько инстансов backend доставляют их своим сокетам. |
| Поиск | PostgreSQL `tsvector` + GIN, префиксный `to_tsquery` | Поиск идёт в БД с пагинацией, фронтенд не грузит историю. |
| Файлы | Docker-том `uploads` (по умолчанию) или внешний S3 (SigV4) | Проверка magic bytes + расширения, лимит размера, перекодирование изображений через sharp, превью, Range-запросы для видео. |
| Frontend | React 19 + TS, собственный store на `useSyncExternalStore`, esbuild | Минимум зависимостей, быстрая сборка. |

## Что реализовано

**Аккаунт и профиль**
- Регистрация (ник, email, пароль+подтверждение, аватар, баннер, цвет, тема) с живым предпросмотром карточки; вход, выход, восстановление пароля по email (Mailpit: http://localhost:8025), смена пароля, список и отзыв сеансов, **2FA (TOTP)**.
- Profile card / popover по образцу скриншота: баннер, аватар со статусом, имя, username, значки с тултипами, свой статус, «обо мне», роли, общие серверы/друзья, быстрые кнопки (друг, ещё) и поле «Сообщение для @…». Расширенный профиль с вкладками.
- Темы профиля: 8 пресетов + свои цвета, градиент/сплошной/изображение, свечение, стиль карточки (обычный/стекло/контур). **Проверка контраста WCAG 4.5:1** на фронте и на бэке.
- Статусы Online / Idle (авто по бездействию) / DND / Invisible + свой статус с эмодзи.

**Серверы**
- Создание, вход по приглашению или из «Обзора» публичных серверов, выход, удаление (только владелец), название/описание/иконка/баннер.
- Роли Owner/Admin/Moderator/Member, 20 прав (Manage Server/Channels/Messages/Roles/Voice/Badges, Kick, Ban, Timeout…), иерархия ролей, UI управления ролями и участниками.
- Приглашения `/invite/XXXX` со сроком и лимитом использований; баны, кик, тайм-аут; журнал аудита.
- **Значки**: создаёт/выдаёт/снимает только MANAGE_BADGES (проверка на backend), иконка, цвет, порядок; показ в карточке, списке участников, тултипы.

**Чат**
- Realtime через WebSocket: отправка (оптимистично, с повтором при ошибке), редактирование, удаление, ответы, ветки (цепочки ответов), реакции, закрепы, закладки, отметка непрочитанным, индикатор набора, slowmode, группировка, разделители дат, бесконечная прокрутка, переход к найденному сообщению с подсветкой.
- Markdown без innerHTML: `**жирный**`, `*курсив*`, `__подчёркнутый__`, `~~зачёркнутый~~`, `||спойлер||`, цитаты, `код`, блоки кода с копированием, ссылки, @упоминания с автодополнением, @everyone (по праву).
- Файлы: drag & drop с оверлеем, вставка из буфера, прогресс загрузки, превью, изображения/видео/аудио/документы, скачивание, удаление. Доступ к файлу проверяется по членству в канале (смена ID ничего не даёт).
- GIF picker: категории, популярные, поиск, бесконечная прокрутка; провайдер Giphy или Tenor, ключ только на backend.
- Эмодзи-пикер с поиском (RU/EN).
- Поиск: люди/серверы/каналы + сообщения с фильтрами От / В канале / До / После / Есть (ссылки, изображения, файлы, GIF), пагинация.

**Личные сообщения и друзья** — запросы, принятие/отклонение, удаление, блокировка, онлайн-статусы, DM со всеми типами контента, непрочитанные, голосовые и видеозвонки со звонком/отклонением/таймером и записью «пропущенный звонок».

**Голос и видео (LiveKit)**
- Голосовые каналы: вход/выход, участники в сайдбаре, **индикатор речи по реальному уровню** (SFU для участников комнаты, AudioWorklet для себя), mute/deafen, серверный мут/оглушение (принудительно через права SFU), перемещение и отключение модератором, тайм-аут.
- **Voice Activity**: собственный граф Web Audio (усиление → «шлюз» → публикуемый трек), VAD с автопорогом по шумовому фону или ручной чувствительностью, гистерезис/hangover.
- **Push-to-Talk**: клавиша/сочетание/боковые кнопки мыши, keydown/keyup, без автоповтора, задержка отпускания, отпускание при потере фокуса; опция «выключать микрофон при уходе из окна».
- Шумоподавление, эхоподавление, АРУ; выбор микрофона/динамиков/камеры (`enumerateDevices`, горячая замена устройства без переподключения), громкость ввода/вывода.
- Индивидуальная громкость 0–100 % на пользователя (и отдельно на трансляцию), локальный мут — только у вас.
- Видео: камера, смена камеры, сетка 1/2/3-4/5+ с подсветкой говорящего, аватар при выключенной камере.
- **Демонстрация экрана** через `getDisplayMedia`: экран/окно/вкладка, **со звуком системы/вкладки** где браузер позволяет (иначе явное сообщение «System audio is not available…»), смена источника, индикатор «Вы демонстрируете экран», одновременно с камерой и микрофоном. По умолчанию **все участники канала сразу видят демонстрацию и слышат её звук** (как общий показ); можно отключить автопросмотр в настройках и смотреть по кнопке. Отдельный **источник звука демонстрации** (BlackHole на macOS, «Monitor of…» на Linux) позволяет передать весь звук компьютера там, где браузер его не отдаёт. Звук идёт в музыкальном качестве: стерео, 128 кбит/с, без шумо- и эхоподавления.
- Fullscreen, нативный Picture-in-Picture (с feature detection), встроенный перетаскиваемый и масштабируемый мини-плеер, фокус-режим, скрытие участников и боковой панели.
- **Качество соединения** из `getStats()` каждые 1.5 с: RTT, джиттер, потери, кодек, битрейт звука, отправка/приём, тип соединения (UDP/TCP, host/STUN/TURN), ICE и DTLS — в панели «Голосовая связь подключена» и окне «Сведения о соединении».
- Переподключение: LiveKit resume/ICE restart; при полном обрыве — повторный вход с новым токеном с backoff; gateway переподключается сам и восстанавливает состояние.

**Настройки** — Моя учётная запись, Профиль, Конфиденциальность, Безопасность, Уведомления (desktop + звуки), Голос и видео (тест микрофона с шкалой `████░░`, «слышать себя», тест динамиков через `setSinkId`, предпросмотр камеры), Внешний вид (тёмная/светлая/OLED, акцент, плотность, шрифт, фон чата), Доступность, Язык, Горячие клавиши.

**Прочее** — уведомления (DM, упоминания, друзья, звонки, счётчики), presence с heartbeat, toasts, скелетоны, адаптив (drawer на мобильных), структурные логи без секретов, логирование ICE/connection/signaling состояний WebRTC.

## Админ-панель и особые значки

Кроме значков сервера (их создают владелец/Admin в «Настройки сервера → Значки»), есть **особые значки платформы** — как Discord Staff: они показываются в профиле человека везде, первыми, с подписью «Значок Concord».

Управляет ими **администратор платформы**: «Настройки пользователя (⚙ внизу слева) → Платформа → Админ-панель». Там:

- **Особые значки** — создать (название, описание, эмодзи, цвет или своя картинка PNG/JPG/WebP/GIF → 64×64), изменить, сменить иконку, удалить; «Выдать / владельцы» — поиск человека и выдача, список владельцев и снятие.
- **Пользователи** — поиск по имени/email/ID, выдача и снятие значков одним кликом, назначение других администраторов.
- **Журнал** — кто, кому и что выдал.

Кто администратор:

- самый первый зарегистрированный аккаунт на новой установке (с демо-данными это `alice@concord.local`);
- все email из `PLATFORM_ADMIN_EMAILS` в `.env` (применяется при запуске backend);
- любой, кому выдали права командой `make admin EMAIL=you@example.com` (снять: `make admin EMAIL=… REVOKE=1`, список: `make admins`) или кнопкой «Сделать админом» в панели.

Все проверки — на backend по базе при каждом запросе; обычный пользователь получает 403 на любые `/api/admin/*`, и пункт меню у него не показывается. Последнего администратора снять нельзя.

## Переменные окружения

Все переменные с комментариями — в [`.env.example`](.env.example). Главное:

| Переменная | Назначение |
|---|---|
| `JWT_SECRET`, `LIVEKIT_API_SECRET` | ≥ 32 символов, сгенерируйте `openssl rand -hex 32` |
| `STORAGE_DRIVER`, `S3_*` | хранилище: `local` (том `uploads`, по умолчанию) или `s3` (AWS S3 / R2 / любой S3-совместимый) |
| `LIVEKIT_NODE_IP` | IP, по которому браузеры достают медиа-порты SFU (127.0.0.1 — только этот компьютер) |
| `TURN_*` | coturn: логин/пароль и внешний адрес |
| `GIF_PROVIDER`, `GIF_API_KEY` | `giphy` или `tenor`; без ключа GIF-панель честно сообщает, что отключена |
| `SMTP_*` | почта для сброса пароля |
| `SEED_ON_START` | демо-данные при первом запуске |
| `PLATFORM_ADMIN_EMAILS` | email-адреса администраторов платформы через запятую (админ-панель, особые значки) |

## Развёртывание на сервере (доступ из интернета)

Так Concord работает как Discord: один сервер в интернете, все заходят по адресу `https://ваш-домен`, общаются, звонят и смотрят демонстрации друг друга.

### 1. Сервер

Любой VPS с Linux (Ubuntu 22.04/24.04 или Debian 12) и **публичным IP**: Hetzner, DigitalOcean, Timeweb, Selectel, Яндекс Облако, AWS и т.п.

| Людей одновременно в голосе | Сервер |
|---|---|
| до ~15 | 2 vCPU, 4 ГБ RAM |
| до ~50 | 4 vCPU, 8 ГБ RAM |

Канал: ~1–3 Мбит/с исходящего трафика на каждого зрителя видео/демонстрации (SFU пересылает поток каждому).

### 2. Домен

Создайте у регистратора DNS-запись **A**: `chat.example.com → IP сервера`. (Cloudflare: «серое облачко», без проксирования — иначе не пройдёт голос.) Без домена можно обойтись: скрипт возьмёт бесплатное имя вида `203-0-113-5.sslip.io`, которое уже указывает на ваш IP.

### 3. Установка одной командой

```bash
scp concord.zip root@SERVER:/opt/ && ssh root@SERVER
cd /opt && apt-get install -y unzip && unzip concord.zip && cd concord
sudo ./scripts/install-server.sh chat.example.com you@example.com
```

Скрипт ставит Docker (если нет), открывает порты в ufw/firewalld, генерирует `.env` со случайными секретами, публичным IP для медиа и TURN, поднимает всё и ждёт, пока заработает HTTPS (сертификат Let's Encrypt выпускается и продлевается автоматически через Caddy).

### 4. Порты

Если у провайдера есть свой firewall / security group — откройте там:

| Порт | Зачем |
|---|---|
| TCP 80, 443 · UDP 443 | сайт, API, WebSocket (HTTPS, HTTP/3) |
| UDP 7882 | голос, видео, демонстрация (основной путь) |
| TCP 7881 | медиа через TCP, если UDP заблокирован |
| TCP+UDP 3478, UDP 49160-49200 | TURN-релей для пользователей за строгим NAT/корпоративным firewall |

### 5. Дальше

- Откройте `https://chat.example.com`, зарегистрируйтесь первым, создайте сервер, отправьте друзьям ссылку-приглашение (`/invite/…`).
- Демо-данные на сервере не создаются (`SEED_ON_START=0`).
- Письма для сброса пароля: заполните `SMTP_HOST/PORT/USER/PASSWORD` в `.env` (любой SMTP: Яндекс, Mailgun, SendGrid…) и `make restart`.
- GIF: получите бесплатный ключ GIPHY или Tenor → `GIF_API_KEY` в `.env`.
- Обслуживание: `make logs`, `make backup` (дамп базы в `./backups`), `make restart` после изменений, обновление — заменить файлы проекта и `make restart` (миграции применяются сами).

## Звук демонстрации — чтобы его слышали все

Демонстрация с включённым автопросмотром работает как общий показ: все в канале сразу видят экран и слышат его звук. Откуда брать звук, зависит от системы того, **кто показывает**:

| Кто показывает | Как передать весь звук |
|---|---|
| Windows, Chrome/Edge | «Весь экран» + галочка **«Поделиться системным звуком»** — работает сразу |
| Любая ОС, Chrome/Edge | показ **вкладки** + «Поделиться звуком вкладки» (видео/музыка в браузере) |
| macOS | установить **BlackHole** (`brew install blackhole-2ch`), в «Настройке Audio-MIDI» сделать «Устройство с несколькими выходами» (динамики + BlackHole) и выбрать его выходом системы; в Concord: Настройки → Голос и видео → **Источник звука демонстрации** → BlackHole 2ch |
| Linux | там же выбрать **«Monitor of …»** (монитор выхода PipeWire/PulseAudio), либо в `pavucontrol` → «Запись» переключить поток браузера на монитор |

Звук демонстрации передаётся отдельным стерео-треком 192 кбит/с без шумо- и эхоподавления (музыка и игры не «режутся») и синхронно с видео (один MediaStream). Тому, кто показывает, лучше быть в наушниках, иначе микрофон повторно поймает звук из колонок. Зрители регулируют громкость демонстрации отдельно от голоса.

### Совместный просмотр фильмов

- **Качество показа** (Настройки → Голос и видео, ПКМ по кнопке демонстрации или кнопка ⏲ на сцене во время показа; меняется на ходу): «1080p · 30 fps» — по умолчанию, для фильмов; «1080p · 60 fps» — игры; «720p» — слабый канал; «Текст и код» — максимум чёткости при 15 fps.
- Для видео кодер держит **частоту кадров** (content hint `motion`), а не чёткость отдельных кадров — без рывков. Трансляция идёт одним слоем высокого качества (без simulcast), поэтому и в мини-плеере, и во весь экран картинка одинаково чёткая. Чтобы фильм шёл плавно, у того, кто показывает, должно быть ~6–9 Мбит/с исходящей скорости (в локальной сети — без проблем).
- Звук собеседников и фильма у зрителей играет через `<audio>`-элементы, а не Web Audio: только так Chrome применяет эхоподавление, и звук из колонок зрителя не возвращается в звонок. Поэтому громкость ограничена 100 %.
- Картинка-в-картинке не замирает при переключении вкладки (видео в фоне не ставится на паузу).
- Мини-плеер всегда остаётся в пределах окна, у него свои кнопки: громкость трансляции, картинка-в-картинке, во весь экран, вернуться к звонку.

## macOS и Linux

Всё запускается одинаково на обеих системах; скрипты совместимы со штатным bash 3.2 в macOS и с GNU-утилитами в Linux.

### Что нужно установить

| | macOS | Linux |
|---|---|---|
| Docker | Docker Desktop, OrbStack или Colima (`brew install colima docker docker-compose && colima start`) | Docker Engine + плагин compose (`docker-compose-plugin`); пользователь в группе `docker` |
| make, openssl | уже есть (Xcode Command Line Tools: `xcode-select --install`) | `sudo apt install make openssl` |
| Архитектура | Apple Silicon (arm64) и Intel — все образы мультиархитектурные | x86_64 и arm64 |

### Команды

```bash
make help        # список команд
make setup       # .env для этого компьютера (http://localhost)
make setup-lan   # .env для доступа из локальной сети (HTTPS через Caddy на LAN-IP)
make up / down / logs / ps / restart
make trust-cert  # доверять локальному HTTPS-сертификату (Keychain в macOS; system store + NSS для Chrome в Linux)
make dev         # запуск БЕЗ Docker (см. ниже)
make test        # unit + API тесты;  make e2e — UI-тесты против запущенного стека
make clean       # остановить и УДАЛИТЬ все данные
```

`setup.sh` сам определяет LAN-IP (`route`/`ipconfig getifaddr` в macOS, `ip route` в Linux), проверяет Docker и занятость портов (`lsof`/`ss`), а в rootless Docker на Linux переключает HTTP-порт на 8080 (порты ниже 1024 там недоступны). Другой порт: `./scripts/setup.sh --port 8080`.

### Почему для сети нужен HTTPS

Браузеры дают доступ к микрофону, камере и экрану только на `localhost` или по HTTPS. Режим `--lan` поднимает Caddy с собственным локальным CA (ничего не запрашивается из интернета) и прописывает IP компьютера в `LIVEKIT_NODE_IP` и настройки TURN, чтобы медиа шло напрямую. Предупреждение о сертификате можно один раз принять или выполнить `make trust-cert`. В этом режиме открывайте только `https://…:8443` (cookie помечены Secure).

### Запуск без Docker

```bash
# macOS
brew install node postgresql@16 redis livekit
brew services start postgresql@16 && brew services start redis
# Linux (Debian/Ubuntu)
sudo apt install postgresql redis-server && sudo -u postgres createuser -s "$USER"
curl -sSL https://get.livekit.io | bash        # livekit-server;  Node 22: nvm install 22

make dev   # → http://localhost:5173, Ctrl+C останавливает всё
```

Файлы хранятся в `.dev/uploads`, TURN не нужен (всё на одной машине).

### Особенности систем

**macOS**
- Первый раз macOS спросит разрешения. Если отказали — Системные настройки → Конфиденциальность и безопасность → **Микрофон**, **Камера**, **Запись экрана и системного звука** → включить браузер и перезапустить его. Приложение распознаёт отказ на уровне системы и подсказывает, куда идти.
- Звук при демонстрации: Chrome/Edge передают звук **только при показе вкладки**; звук всего экрана в macOS браузерам недоступен (приложение об этом сообщает). Safari звук демонстрации не передаёт.
- Safari: выбор устройства вывода не поддерживается — звук идёт в системное устройство; остальное работает.
- Горячие клавиши показываются символами ⌃ ⌥ ⇧ ⌘; по умолчанию используется Control, чтобы не пересекаться с ⌘-сочетаниями браузера.
- Порт 5000 в macOS занят AirPlay Receiver — не используйте его для `--port`.
- Docker Desktop пробрасывает UDP-порты 7882 и 3478; с OrbStack/Colima тоже работает.

**Linux**
- Демонстрация экрана на **Wayland** идёт через xdg-desktop-portal + PipeWire (в GNOME и KDE уже установлены); на X11 работает напрямую. Звук — только при показе вкладки Chrome/Chromium; Firefox звук демонстрации не передаёт.
- Микрофоны/динамики берутся из PipeWire/PulseAudio; если устройство не видно — проверьте `pactl list short sources`.
- Самоподписанный сертификат в Chrome на Linux надо добавить в NSS — `make trust-cert` делает это через `certutil` (`sudo apt install libnss3-tools`).
- Если включён firewall (ufw/firewalld), для доступа из сети откройте: 8443/tcp, 7881/tcp, 7882/udp, 3478/tcp+udp, 49160-49200/udp.

## Как проверить голос

1. `make up`, откройте http://localhost в двух окнах **разных профилей браузера** (или обычное + инкогнито).
2. Войдите как `alice@concord.local` и `bob@concord.local` (пароль `demo12345`).
3. Demo Server → 🔊 General у обоих. Разрешите микрофон.
4. Говорите: подсвечивается аватар и строка в сайдбаре у собеседника; внизу «Голосовая связь подключена» и пинг.
5. Нажмите значок сигнала — «Сведения о соединении» с реальными RTT/джиттером/потерями/битрейтом.
6. ПКМ по участнику → громкость 0–100 %, «Заглушить для себя». Alice (Owner) видит серверный мут, перемещение, отключение.
7. Настройки → Голос и видео → «Режим рации», клавиша V: звук идёт только пока клавиша зажата.

С другого устройства в сети: `./scripts/setup.sh --lan --force && make up`, затем `https://<IP>:8443` на телефоне или втором компьютере.

## Как проверить демонстрацию экрана

1. В голосовом канале нажмите «Демонстрация экрана».
2. Chrome/Edge: выберите **вкладку** и включите «Поделиться звуком вкладки», или **весь экран** с «Поделиться системным звуком» (Windows/ChromeOS). Окна приложений звук не отдают — Concord покажет сообщение об этом.
3. У остальных участников плитка «LIVE» появляется сразу, звук демонстрации слышен без лишних кликов; его громкость регулируется отдельно (значок динамика на плитке), «Прекратить просмотр» — если не хотите смотреть.
4. Попробуйте: «Сменить источник», камеру одновременно с экраном, «Развернуть», fullscreen (двойной клик), PiP, мини-плеер при переходе в другой канал, кнопку «Прекратить просмотр».

Работа велась в изолированной среде без доступа к npm/Docker Hub и без Docker-демона. Поэтому:

- **Не удалось запустить здесь:** сам LiveKit SFU, coturn и `docker compose up` (образы недоступны). Поэтому реальный звонок между двумя людьми, демонстрация экрана через SFU и TURN-relay **не проверены в этой среде** — их нужно проверить у вас по шагам выше; в E2E без SFU проверяется, что клиент честно показывает «Не удалось подключиться к голосовому каналу», а не фейковое подключение. `docker compose config` валиден.
- Серверный режим: `setup.sh --server` (с доменом и без) и `docker compose config` с профилем `server` проверены; реальный выпуск сертификата Let's Encrypt и звонок через интернет здесь проверить невозможно (нет публичного IP и Docker) — это первая проверка после установки на VPS.
- Скрипты: `setup.sh` (все режимы), `dev-native.sh` (с заглушкой вместо livekit-server) и `Makefile` прогнаны на Linux; `docker compose config` валиден с профилем https. На macOS запустить их здесь было негде — они написаны под bash 3.2 и BSD-утилиты, но первый запуск на Mac стоит считать проверкой.
- Типы `pg`/`ioredis`/`ws`/`react`/`livekit-client` здесь проверялись по локальным декларациям; полный `npm run typecheck` с официальными `@types` стоит прогнать после `npm install`. Сборка в Docker идёт через esbuild и от проверки типов не зависит.

## Известные ограничения

- Браузер сам отдаёт звук всего экрана только в Chrome/Edge на Windows (и ChromeOS), звук вкладки — везде в Chrome/Edge. На macOS и Linux весь звук компьютера передаётся через «Источник звука демонстрации» (BlackHole / Monitor of…) — это один раз настроить, но без нативного приложения иначе нельзя. Firefox и Safari звук демонстрации сами не передают (через «Источник звука» — передают).
- Push-to-Talk работает, пока вкладка в фокусе: браузер не получает нажатия клавиш из других окон (это ограничение веба, не приложения).
- Выбор устройства вывода (`setSinkId`) — Chromium-браузеры; в остальных используется системное устройство с сообщением в настройках.
- Медиа доступны только на `localhost` или по HTTPS.
- Собственные эмодзи сервера и опросы (polls) не реализованы; ветки — это цепочки ответов на сообщение, а не отдельные каналы.
- Интерфейс только на русском (выбор языка влияет на язык поиска GIF).
- 2FA — без QR-кода (секрет и ссылка `otpauth://`).
